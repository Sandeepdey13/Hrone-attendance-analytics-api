# Starter Review

| # | Where | What is wrong | How to notice | Fix applied |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Uses the punch-in's local calendar date as the shift start date, so IST and overnight shifts are wrong. It also floors elapsed minutes before applying the strict 10-minute grace rule. | For a 09:30 shift, 09:40:01 must report 10 minutes late; for a 22:00-06:00 shift, a 00:30 punch belongs to the prior day's shift. | Normalize UTC instants, derive the attendance date in IST, truncate to seconds, then apply the grace rule before flooring. |
| 2 | `compute_work_hours` | Uses Python's ties-to-even `round` and doesn't first truncate timestamps to whole seconds. | A duration of 4:30:18 is 4.505 hours and must round to 4.51. | Calculate from truncated seconds with `Decimal` and `ROUND_HALF_UP`. |
| 3 | `compute_overtime` | Omits the 30-minute minimum, anchors every shift end to the same date, and subtracts aware from naive datetimes. | A punch-out 29 minutes after shift end should give zero; a 22:00-06:00 shift ends the next day. | Use UTC-aware instants, move overnight shift end to the next day, and apply the 30-minute threshold. |
| 4 | `health` | Returns ready without checking MongoDB. | Stop MongoDB; the starter still returns 200. | Ping the database and return 503 if it is unavailable. |
| 5 | Startup / indexes | Creates no indexes, so employee lookup and attendance listing lack the required query support and uniqueness guarantees. | Inspect indexes in a clean database; only MongoDB's default `_id` index exists. | Create idempotent indexes at startup, including unique employee and employee/date keys. |
| 6 | `create_employee` | Performs a duplicate check before insert, which is not concurrency-safe; accepts unchecked fields; stores naive local `created_at`; and returns it in the wrong timestamp format. | Concurrent duplicate creates can both pass the check; malformed codes/dates or a non-UTC host expose the other issues. | Validate the request, store UTC BSON time, serialize epoch milliseconds, and map unique-index conflicts to 409. |
| 7 | `list_employees` | Starts page 1 after the first page, reports the unfiltered total, lacks contract sorting, and does not constrain pagination. | Compare pages with more than one page of employees or filter to a small department. | Use `(page - 1) * page_size`, count the same filter, sort by `emp_code`, and validate page bounds. |
| 8 | `punch_in` | Unknown employees cause a 500; host-local timestamps produce the wrong IST day; statuses/timestamps are weakly validated; and a read-before-insert check can race. | Try an unknown code, an overnight punch, invalid timestamp types, or parallel punches for one day. | Validate strictly, return 404 for unknown employees, derive the IST day, and enforce unique `(emp_code, date)` in MongoDB. |
| 9 | `punch_in` response | Exposes a synthetic `id` based on MongoDB `_id`, which the contract excludes. | Inspect a successful response. | Return only the contract fields; address records by `(emp_code, date)`. |
| 10 | `list_attendance` | Reads every matching document into Python before sorting and paging; it also returns database internals and does not validate date ranges or pagination. | Request a small page from a large collection or use a reversed date range. | Validate inputs, count in MongoDB, and apply indexed sort/skip/limit before serialization. |
| 11 | `list_attendance` | Sort order and response shape don't match the contract. | Create multiple employees' records for the same day and inspect timestamps and IDs. | Sort date descending then `emp_code` ascending, serialize times as epoch milliseconds, and omit `_id`. |
| 12 | `app/main.py` | Punch-out, regularization, all analytics, and explain endpoints are absent. | Call any endpoint marked for implementation in the assignment. | Implemented the remaining routes with atomic updates and MongoDB aggregation pipelines. |

## Reviewed and Kept

The default shift times (`09:30` and `18:30`) and the initial open-record values (`punch_out`, `work_hours`, `overtime_minutes`, `half_day`, and `history`) match the contract. I retained those defaults.
